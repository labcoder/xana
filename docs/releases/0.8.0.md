# Xana 0.8.0 — Memory and local autonomy

Xana can now retain scoped personal preferences, work from selected knowledge,
and carry out explicitly authorized local background tasks. These capabilities
share the same protected storage, permissions and budgets as interactive work.
For example, ask Xana to remember a preference, recall a selected project note,
search for current information, or create a bounded scheduled task.

## What's new

- **Scoped personal memory:** model-selected recall/save/correct/forget tools,
  source-attributed receipts, independent learning/use controls, and exact undo.
  Memory lives in Xana's protected home, not a generated workspace preferences
  file. Rejected or unavailable mutations cannot loop without bound.
- **Protected storage and recovery:** fresh setup generates keys in OS custody;
  existing homes use a reviewed migration. Encrypted history, artifacts, indexes
  and backups retain stable identities, with explicit locking and independent
  recovery-key export. You do not need to invent a password.
- **Context and knowledge:** bounded lexical recall over retained project work
  and selected Markdown/text sources, lazy original-proof paging, and optional
  evaluated semantic compaction without replacing raw history. Helper routes
  require explicit authorization; a missing or failed helper is not silently
  replaced with a paid provider call.
- **Local autonomy:** durable scheduled jobs, selected-file and named GitHub CI
  triggers, retained child follow-ups, cumulative usage admission, and visible
  pause/cancel/needs-you outcomes. Unknown effects are not automatically replayed.
- **Honest completion:** evidence distinguishes an answer from verified work,
  unresolved checks and uncertain effects. Ordinary chat has no invented
  correctness score, and safety approvals still apply.
- **Web basics:** configurable bounded search, public-page extraction, scoped
  turn consent, bounded redirects and readable failure/progress feedback.
  Search/fetch do not require a browser. An unconfigured search route explains
  what to configure instead of disguising guessed URLs as search results.
- **Conversation reliability:** compatible native settings apply between turns
  without replacing history. Startup/readiness, storage onboarding, memory-tool
  recovery and provider-stream handling are hardened. Interactive command
  dispatch isolates large Rust futures to prevent the empty-chat stack overflow;
  the regression exercises a real terminal process, not only rendered fixtures.
- **Release safeguards:** native archive audits require the exact planned
  executable version, with checksum, inventory and help checks before assembly.

## Upgrading and limits

Run `xana storage status` and `xana doctor` after updating. Existing plaintext
homes are not silently migrated: follow [protected storage and recovery](../user/protected-storage.md).
Keep an independent recovery key **and** encrypted data backups. Exporting the
key is not backing up conversation data; deferring it leaves OS-key loss as a
recovery risk. Nothing here migrates or grants access to vendor-owned stores.

Model quality still matters, particularly for small local models' tool choices.
Bounded recovery prevents runaway retries; it does not guarantee a correct
answer. Automatic learning, explicit memory tools and task-history compaction
are separate mechanisms, not unlimited or infallible memory. See
[personal memory](../user/personal-memory.md),
[semantic compaction](../user/semantic-compaction.md),
[durable schedules](../user/durable-schedules.md) and
[public web tools](../user/public-web.md).

The native archives contain the terminal application. GPUI Desktop remains
source-built in the same repository; see the [Interfaces notes](0.7.0.md).
Desktop visual polish, assistive-technology evidence, loaded-client frame-rate
qualification and local web remain deferred. Broader browser control and Unix
browser parity are also deferred; the optional existing Windows adapter is not
a cross-platform browser promise. Remote hosts and the future Harness Laboratory
are not shipped by this release. Manual UI/account/OS-interaction observations
remain separate from automated tests and hosted resource measurements.

## Preview trust limits

This is an unsigned developer preview. macOS builds are not notarized; Windows
executables are not Authenticode-signed. Checksums and GitHub attestations verify
asset identity/provenance, not OS publisher approval. Do not disable host security
controls to install it. Package-manager channels, automatic updates and a support
SLA remain future distribution work.
